## Was „verifiziert“ hier bedeutet

Jedes AC besitzt einen Scope. 100 erfolgreiche Zyklen im integrierten Chromium
beweisen die freigegebenen Ressourcen dieses Builds auf diesem Gerät. Sie messen
weder den Treiberspeicher noch alle internen Browser-Listener. `npm run check:release` bleibt bei offenen AC ausdrücklich rot; der Konsistenzchecker allein erteilt keine Releasefreigabe. Die verwendeten
Glyph-Pufferbytes werden separat ausgewiesen. Ein konstanter eigener Ressourcen-
bestand beweist keine pauschale Speicherüberlegenheit gegenüber DOM-Oberflächen.

Adaptertests prüfen Ausführungsgrenzen und Konkurrenz unabhängig von der GPU.
Der Host muss einen vertrauenswürdigen Auth-Kontext bereitstellen; eine Zod-
Validierung eines Principal-Strings authentifiziert keinen Browserrequest.
Produktive Anbieteraktionen brauchen einen dauerhaften Idempotenzspeicher.

## Konkrete Fortsetzung der offenen Waves

1. **RP1/T05–T07:** echte Scroll-/Clipping-/Virtualisierungs-Conformance, nicht nur
   die Berechnung eines Virtual Range; RTL/CJK, Fontfehler-Isolation, vollständige
   Tastatur-/IME-/Screenreader-Journeys und mobile Eingabe auf der Supportmatrix.
2. **RP2/T09–T14:** volle Component-/Content-/URL-Verträge einschließlich Popup-
   Presence, Unterbrechungen, Content-Mappings und aller Komponentenfamilien.
3. **RP3/T16–T20:** Projektverzeichnis und atomare Revisionen, vollständiges
   Authoring/Undo/Redo, persistente Runs/Replay, CLI `init/add/studio/export`.
   Aktuelle Projektanzeige ist noch kein fertiger visueller Editor.
4. **RP4–RP5/T21–T30:** Top-k-Intent, budgetierter Preload, echte serverseitige
   Provider-Orchestrierung, Kostenreservierung, Telemetrie und qualifizierte
   Experimente. Synthetische Cases ersetzen keine dieser Produktionsabnahmen.
5. **RP6–RP8/T31–T38:** Collaboration, Plugins, Enterprise, zusätzliche Eingaben,
   XR-/Neural-Research und abschließende Registry bleiben eigene Releasepakete.

Externe Voraussetzungen sind konkrete freigegebene Anbieterzugänge, zusätzliche
Testgeräte/Assistenztechnologien und für XR ein nachgewiesenes Headset-/Browserprofil.
Daraus folgt keine Abnahme der intern noch offenen Implementierungen.
